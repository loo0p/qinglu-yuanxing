我想做一款叫《云岫小筑》的修仙文字探索经营游戏，使用 Godot 开发，导出 H5，在浏览器里直接玩，优先适配手机。

一、我想要的核心体验

参考《梅尔沃放置》的技能成长、资源生产和长期积累，但保留修仙世界里的旅行、机缘和小筑经营特色。

我希望形成这样的循环：
经营小筑、采集生产 → 为探索做准备 → 在外面作出有意义的选择 → 获得新方法、资源、关系或世界变化 → 回来调整经营与修炼 → 向更远的目标推进。

探索和经营不能是两个互不相关的小游戏。探索带回的东西，应在后续玩法里真正有用；经营的成果，也应让我能以不同方式探索，而不只是数字越来越大。

二、目前最需要解决的问题

1. 探索不能只是反复点击“探索”，看随机文案、拿材料，再重复。
2. 要有清楚的目标感：我现在为什么做这件事？做完能发生什么变化？下一阶段值得期待什么？
3. 选择要有可理解的代价和后果，例如保留资源、改变路线、影响当地环境或人物、选择不同成长方式。不能只是换一句台词。
4. 修炼节奏要合理，不能一会儿就金丹，也不能靠把等待时间拉长来凑内容。
5. 新开游戏、重开档和继续游戏的入口必须明显，不能藏在难找的菜单里。

三、主要系统

- 开局引导：通过真实玩法，让玩家自然理解探索、生产和修炼，不要先塞一大堆说明。
- 小筑经营：有相互联系的采集、种植、炼制和设施生产链。资源有不同用途，需要做取舍，而不是无脑把所有建筑点满。
- 技能与专精：通过实际做事成长，解锁新的方法和不同发展侧重，不只是统一加百分比。
- 修炼成长：有境界、突破与阶段解锁，长线以飞升为目标。每个阶段应带来玩法变化，不只是换名字、提高价格。
- 探索：有地点差异、机缘、路线和后果。允许一次性事件，也允许熟悉后的重复采集，但重复劳动应该能批量安排，不要求每次手点。
- 阶段衔接：新方法要在玩家还有相关需求时出现，不能等需求结束了才解锁。
- 存档：浏览器中可靠保存，刷新、关闭再开、切到后台恢复后行为合理。新开档前清楚说明影响。

四、我更早提出过的完整愿景

玩家是一位可自定义的女修，在修仙世界中旅行、修炼、结交和影响别人。

我希望最终有随机地图和事件、不同门派与修炼构筑，以及有性格、记忆、所求和关系变化的 NPC。人物可以查看生平记事，记事里的其他人物能点击跳转。

曾提出至少100位 NPC、可组合的上半身动态头像，以及约5–6小时单局内容的目标。头像希望有自然错开的眨眼、轻微发丝或衣袖动作，五官协调、风格统一。

这些属于长期愿景，不要为了第一版凑数量而做一百个空壳人物，也不要拿生成事件数量或自动测试次数充当游戏时长。先把核心流程做得少而精，再扩展。

五、画面与操作

文字和界面为主，不需要大型2D场景。当前视觉方向是清透国风，保持统一、轻盈、有修仙生活感。

手机上要好用：顶部不要占太多空间，列表滑动顺畅，关键操作不用到处翻找，图标有清楚含义，按钮有点击反馈和适量音效。文案自然，不要堆砌空泛的“AI味”词汇。

早期提过《RimWorld》的世界与人物互动、《极乐迪斯科》的美术质感，可作为局部参考，但不要因此覆盖现在的修仙探索经营定位，也不要改成动作游戏或纯解谜游戏。

六、请按这个流程做

先不要急着写代码，也不要继续零碎修补。

先提出从开局到飞升的完整玩法方案，具体说明：
- 玩家每个阶段看见什么、想做什么、实际做什么。
- 探索有哪些真正不同的选择，后果如何进入后续玩法。
- 生产、技能、修炼和阶段目标怎样互相支撑。
- 每种资源的来源、用途和主要瓶颈。
- 哪些部分有趣，哪些可能只是重复点击或等待。
- 第一段完整可玩内容做什么，以及怎样验证它。

方案经过评审、修改和复审后，再实现一个从目标到结果都完整的玩法片段。不要每个系统做一点，却没有一段能完整体验。

做数值检验时写清初始条件、成本和假设，不要靠人为增加限制来证明某个设计好。数值成立与实际好玩要分开验证。

七、边界与验收

- 不需要旧档适配或迁移，新版本按新档验证；但不要擅自清空原有存档。
- 不增加付费服务或未经允许的外部权限。
- 我不提供自己的电脑，使用你的开发环境。
- 必须区分设计草案、候选代码和已经发布的版本。
- 浏览器存档、生命周期和手机操作要实际验证。Linux原生运行不等于H5通过，模拟触摸不等于安卓真机测试。
- 不要把未验证的头像、手机表现或数值问题说成已经修好。

现有原型里的固定资源数、建筑格数、配方、人物数量和具体剧情节点，都可以重新评估。不要把前一个 AI 提出的未验证方案当作我已经批准的需求。
