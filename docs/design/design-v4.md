# 《青庐远行》设计 v4：随机人物 × 自转世界 × 说书人 × 生平

> 状态：**设计稿（待 Gemini / DeepSeek 评审）**，未进游戏。附两个原型：叙事模拟 `sim/story_sim.py`、立绘拼装 `portrait/cut_parts.py`。
> 日期：2026-10-21（北京时间）。取代 v3.2 的“固定手写剧本”方向；**保留**青庐经营循环、v0.4/v0.5 的水墨画风与场景化 UI。
> 技术栈依据：`oss-survey.md` 第 5 节。原则：**能用开源就用，不自造对话脚本引擎和骨骼动画引擎**；每个子系统都留一个“接缝”，后面换库不动其他层。

## 0. 一句话与变化

**一句话**：一个女修在青庐落脚，山外的修仙界自己在转——每局遇到的人不同，人会记仇、记恩、结侣、反目、坐化、飞升；说书人看着局势挑事，事后果会接着长出后续；每个人都有一本自己的生平。

| | v3.2（已弃） | v4 |
|---|---|---|
| 内容 | 19 个手写事件，固定顺序 | ~30 个**事件模板**，按状态选角、分支、连锁 |
| 人物 | 固定 4 人 | 开局按种子生成 20 人，世界里陆续出现新人 |
| 世界 | 只有玩家在动 | **WorldTick**：NPC 离屏修炼、游历、争斗、结侣、死亡、飞升 |
| 节奏 | 地图路线 | **说书人**按张力曲线挑事（RimWorld / SS14 思路） |
| 记录 | 行记 | 人人有**生平**、记忆、关系；玩家可以翻任何认识的人 |
| 立绘 | 固定 5 张 | **种子拼装纸娃娃**（部件 + 运行时换色），玩家可随机+微调 |

## 2. 数据模型

全部可序列化成 JSON；存档 = 世界种子 + 增量（人物状态、关系、记事、队列）。字段名用英文，展示文本用中文。

### 2.1 Character（人物，玩家与 NPC 同构）
```json
{
  "id": 17, "is_player": false, "seed": 918273,
  "name": "沈知微", "title": "", "sex": "女", "age": 41.2,
  "origin": {"sect": "玄霜谷", "side": "正", "birthplace": "云梦泽"},
  "realm": {"lv": 10, "xp": 31.5, "injured_days": 0},
  "traits": ["淡泊", "记仇"],
  "likes": ["梅花", "旧书"], "dislikes": ["烈酒"],
  "goal": {"id": "报仇", "target": 9, "progress": 0.3},
  "place": "寒潭", "alive": true, "fate": null,
  "portrait": {"seed": 918273, "overrides": {"hair_front": "f_bun_02", "robe_color": 3}},
  "relations": {"9": "rel"}, "memories": ["mem"], "chronicle": ["entry"]
}
```
- **境界**：`lv` 0–8 炼气一至九层，9–11 筑基，12–14 金丹，15–17 元婴，18 化神。大境界有失败率（失败→受伤，小概率走火身死）。寿元按境界上限。
- **性格**（14 个，2 个/人，排除矛盾组合）：温柔、傲气、多疑、贪财、侠义、痴情、记仇、淡泊、嗜战、好奇、怯懦、圆滑、阴狠、薄情。每个性格有：①选项倾向（kind/brave/careful/greedy/proud/love/revenge/curious 加权），②**欣赏**的性格，③**厌恶**的性格。
- **目标**（8 个）：求长生、寻道侣、振兴师门、寻亲、炼一炉九转丹、收个好徒弟、报仇（带 target）、游遍云梦泽。目标驱动离屏“独角戏”记事与部分事件选角。

### 2.2 Relation（单向；A 对 B 的看法）
```json
{"favor": 35, "grudge": 0, "tags": ["道侣"], "met": true, "since_day": 12, "last_day": 80}
```
- `tags`：道侣、师、徒、结义、仇（结构化关系），可多选。
- **看法 opinion(A→B)** = favor − 1.2·grudge + 性格相合（欣赏 +6 / 厌恶 −8，逐对计）+ 关于 B 的记忆权重之和 − 正魔对立 10。
- 反应全部从 opinion 读：结侣（双方 >35、异性、单身）、结义（同性 >40）、站队、背弃、赠礼回应、心魔内容。

### 2.3 Memory（记忆；Generative Agents 打分）
```json
{"day": 19, "about": 1, "text": "重伤时楚兰救了我", "weight": 30, "importance": 8, "tags": ["救命"]}
```
- 每人最多保留 24 条，满了丢“|weight| − 时间衰减”最低的。
- 检索：`score = 0.5·新近(0.97^天数) + 0.3·重要(importance/10) + 0.2·相关(是否涉及在场的人/当前事件标签)`，取前 k 条。用于：NPC 台词“想起什么”、心魔幻象、旧物、遗言。

### 2.4 ChronicleEntry（生平记事）
```json
{"day": 66, "place": "青庐", "actors": [1, 23], "verb": "报恩", "text": "白婉找到青庐，放下一份木簪……", "mood": "暖", "importance": 6, "public": false}
```
- 每个参与者各写一条（视角不同、措辞不同）。`importance ≥ 7` 的进入“大事记”；`public` 的进入**传闻池**。
- 结构化字段（verb/actors）供故事筛选器识别“故事弧”，如：`救命→报恩→表白→道侣`、`被劫→仇人上门→再上门`、`旧友死→收殓→寻凶`。识别出的弧升格为**称号**（“寒潭救命之交”“负心人”）写进人物卡。

### 2.5 EventTemplate（事件模板）
```json
{
  "id": "qiuzhu", "name": "求助", "tier": 1, "tension": 8,
  "earliest_day": 0, "cooldown": 12, "max_occurrences": 99, "weight": 2,
  "roles": {
    "B": {"pool": "npc", "where": ["injured_days>0", "not_remembers(P)"], "prefer": "injured", "fallback": "any_unharmed_by_P"}
  },
  "weight_mods": [{"if": "B.injured_days>0", "mul": 2.5}],
  "dialogue": "res://events/qiuzhu.dialogue",
  "outcomes": {
    "help": {"effects": ["P.injured+=3", "favor(B,P,+25)", "remember(B,P,'重伤时{P}救了我',30)"], "chain": [{"id": "baoen", "delay": [8, 25]}]},
    "half": {"effects": ["favor(B,P,+8)"]},
    "rob":  {"effects": ["favor(B,P,-50)", "grudge(B,P,+60)", "P.lingshi+=rand(20,60)"], "chain": [{"id": "chouren_shangmen", "delay": [15, 40]}]}
  },
  "chronicle": {"P": "#help_line#", "B": "重伤倒在#地点#，被#P#所救。"}
}
```
- **roles**：选角查询（借 Felt 的“前置条件查询”思想）。`pool` = npc / known / partner / master / enemy_of(X) / dead_known；`where` 是条件表达式；没有合格人选 → 模板不可用。
- **outcomes**：效果是一组小函数（favor、grudge、remember、tag、injure、kill、move、give、schedule），GDScript 实现，DM4 对白只回传 outcome id。
- **chain**：排程后续事件，带延迟区间；到期时若角色已死，后续自动作废或换成“遗物/死讯”变体。
- **world 模板**：同样格式，但 `pool` 只有 NPC，没有玩家选择，按性格权重直接掷结果（离屏）。

### 2.6 Storyteller（说书人）
```json
{"persona": "青灯", "tension": 10, "since_major": 0, "adapt": 0.0,
 "params": {"base_p": 0.35, "major_after": 14, "calm_above": 60, "novelty_tau": 12}}
```
- 每天：先执行到期的连锁；否则以 `base_p + since_major·0.012` 的概率出事件。
- **想要的强度**：`since_major > major_after` 时 50% 要大事（tier 2）；`tension > calm_above` 时只给日常（tier 0，喘息）；其余随机小事。
- **候选权重** = 模板权重 × 状态修正 × 强度匹配（同档 1，相邻档 0.25）× **新鲜度** `1 − e^(−距上次/τ)`；受 `earliest_day / cooldown / max_occurrences` 约束（SS14 字段）。
- **适应度（adapt）**（RimWorld）：玩家顺风（境界领先、关系网大、近期无伤）时缓慢上升，提高 tier 2 与敌对模板权重；受重创/亲友死亡后下降。
- 三种人格（开局可选，存档可改）：
  - **青灯**（≈Cassandra）：张弛有度，默认。
  - **流云**（≈Phoebe）：喘息长、大事少，适合想慢慢经营的人。
  - **掷骰**（≈Randy）：不看曲线，纯按权重。
- 张力：事件自带 tension 增减（心魔、报恩、表白为负，袭镇、寻仇为正），每天无事 −2。

### 2.7 WorldTick（离屏世界）
每游戏日对所有 NPC：
1. 修炼：xp += 随机(0.6–1.4)×(受伤 0.4)；满了升级；大境界 45% 失败。
2. 寿元：超出上限每日 2% 坐化；化神每日 1% 渡劫飞升。
3. 游历：6% 换地点（40% 回宗门）。
4. 相遇：同地 ≥2 人，按人数概率触发一次 **world 事件**；同一对 20 天冷却。种类按 opinion 加权：论道、争宝、斗法（可能致死）、结为道侣、收徒、结义、背弃、复仇。
5. 独角戏：每人每天 1.2% 推进个人目标，写一条生平（“丹炉又炸了，眉毛燎去半边。”）。
6. 新人：每天 4% 有新人入世（人口上限 30），保证每局人物流动。
7. 死亡/飞升/结侣写入**传闻池**，说书人用“坊市传闻”“旧友死讯”“飞升异象”把离屏世界带到玩家面前。

性能：手机 Web 单线程，30 人 × 每日 O(n) + 相遇 O(地点)，GDScript 估计 <1 ms/日；“快进 10 日”也无压力。离屏也可改成按“旬”批处理。

### 2.8 Chronicle UI 数据（见第 6 节）
- 人物卡读 Character；关系页读 relations + opinion；生平页读 chronicle（倒序、按年分组、大事加粗）；“她记得你的事”读 memories 前 3 条。

## 3. 约 30 个事件模板（目标文风）

文风：女修小说的轻、短、留白；**每条生平一两句**；称呼与措辞由 GDTracery 变体与人物性格填入。`P`=玩家，`B/A/M`=选角。T=强度档（0 日常 / 1 小事 / 2 大事）。

### 3.1 结识与人情
1. **偶遇**（T0）B=未结识 NPC。“山道上遇见#B#，#B.性格开场#。”——结伴走一程（+好感，记忆“同行过一段山路”）/ 拱手别过。*开场句随性格*：温柔“她把伞往你这边偏了偏”，傲气“对方只抬了抬眼”，贪财“目光在你的储物袋上停了一停”。
2. **求助**（T1）B=受伤者优先。“#B#倒在青庐柴门外，血把门槛洇深了一块。”——渡灵气（−3 日修为，排程**报恩**）/ 留药就走 / 搜走储物袋（排程**仇人上门**）。
3. **报恩**（连锁，T1）“#B#找到青庐，放下一份#B.喜好#：『那日的事，我记着。』”若好感>50 且异性单身→排程**表白**。
4. **仇人上门**（连锁，T2）“#B#寻上青庐，剑没出鞘，先把你的灯吹了。”——迎战 / 原样奉还再添一成 / 从后窗走（20 日后再来）。
5. **赠礼**（T0）投其所好：命中喜好“回信只有两个字：『正好。』”；命中厌恶“东西被原样退回”。
6. **访客**（T0）熟人路过讨一碗茶；好奇的人“问了很多你炉子的事”，淡泊的人“喝完就走了”。
7. **义结金兰**（T0）同性、opinion>45。“在桂树下撮土为香。”
8. **表白**（T2）异性、好感>45、双方单身。“#B#在桂树下问你愿不愿意同修。”——应下（道侣）/ “道还长。”

### 3.2 争与仇
9. **朱果之争**（T1）后山/寒潭/古战场。让 / 各凭本事（胜负看境界+骰）。
10. **站队**（T1）两 NPC 仇怨≥30 且你认识其一。帮 A / 帮 B / 绕路。**同时结交与结仇**。
11. **劫修拦路**（T0）魔道或阴狠者。“交了买路钱。”记仇 +15，日后可触发寻仇。
12. **坊市欺客**（T0）贪财/圆滑者。“回来才发现灵草是染了色的。”
13. **寻凶**（连锁，T2）旧友被某人所杀。去讨说法（可斩、可败）/ “把他的名字刻在丹炉底下”（40 日后再排程）。
14. **背后一推**（秘境分支）“出秘境时，#A#在背后推了你一把。”——写进双方记忆，心魔素材。

### 3.3 情与侣
15. **道侣口角**（T0）结果看 opinion：<30 “谁也没服谁”；否则“第二天灶上多了一碗粥”。
16. **道侣遇险**（T2）“#B#在云梦泽失了消息。”——去寻（九天，找到人）/ 等消息（40% 永失，否则回来但“没提路上的事”，好感−15）。
17. **负心**（world→玩家可见）道侣有薄情/阴狠，30% 背弃；被负者若痴情/记仇→目标改为**报仇**。玩家若被负，进入“心魔”素材与仇人链。
18. **旧人来信**（T0）离别的道侣/义亲来信，措辞取对方关于你的最高权重记忆。

### 3.4 师徒与宗门
19. **拜师**（T1）你无师，B 高你 6 层以上且非魔道。“#B#说你根骨尚可，收你为记名弟子。”
20. **师父考验**（连锁）“命你在寒潭坐满七日。”坐满（修为+，师父好感+）/ 第五日起身走了。
21. **师门书信**（T0）“#B#从#B.宗门#来信，说师门近来不太平。”（为后续宗门事件铺垫）
22. **宗门大比**（T0 传闻）偏向熟人夺魁；熟人夺魁时可去道贺。

### 3.5 世界与生死
23. **坊市传闻**（T0）把近 15 日传闻（优先你认识的人）说给你听。**离屏世界的窗口**。
24. **旧友死讯**（T2）认识且有好感的人已离屏死去。“听说#B#——#B.死因#。”——去收殓（若有凶手→排程寻凶）/ 遥遥一拜。
25. **飞升异象**（T0）有人飞升后 5 日内。“夜里天边亮了一道光。你在院里站了很久。”
26. **魔修袭镇**（T2，每局一次，20 日后）M=比你高 2 层的魔道。守镇口（与你友好的正道 NPC 闻讯赶来）/ 背姑母进山。
27. **古战场秘境**（T2，最多 3 次）一次结识 3 人；随机产生“拉你一把”或“推你一把”。

### 3.6 青庐日常与内心
28. **姑母来信**（T0）“只写了『冷了加衣』四个字。”
29. **夜雨 / 旧物**（T0）随机拎回一个你认识的人：“灯花爆了一下。你没来由地想起#B#。”/“窗台上那只纸鹤，是#B#折的。”
30. **心魔**（T1，张力>45）幻象取你**最痛的记忆**：“闭关时心魔起，幻出的是：秘境里沈微推我。”——直视（60% 散去）/ 闭目诵经。
31. **灵田 / 闭关小成**（T0）经营与修炼节奏点。

**world 模板（离屏，无玩家选择）**：论道、争宝、斗法、结为道侣、收徒、结义、背弃、复仇、坐化、飞升、走火、新人入世、目标独角戏（8 个目标各 2 句以上）。

**原型暴露的问题（要在实现里解决）**
- 早期版本 NPC 同一对反复斗法 → 已加“同对 20 日冷却 + 败者回宗门”。
- 袭镇一局两次 → 已加 `max_occurrences / earliest_day`；同一对 NPC 反复“站队” → 每对只问一次。
- “宗门大比”传闻 100 日内出现 4 次，偏多 → 传闻类模板要加 cooldown（≥20 日）。
- 模拟玩家是“随性格掷骰”，会出现“救了又劫”这种不连贯人设；真人玩家不会，但 NPC 也需要**一致性**：选择时加“与过往行为一致”的权重。
- 世界道侣对偏少（opinion 门槛与相遇冷却叠加），需要调参或加“同门日久生情”的 world 模板。
- 离屏记事目前是一句话一条；要加**故事筛选器**把同一对人的 3 条以上记事升格为“他们之间的故事”。

## 5. 立绘：种子纸娃娃

### 5.1 固定半身模板与部件清单
统一画布 1024×1365（3:4），头顶留白 6%，**两眼中心与下颌点坐标固定**（所有部件都对齐这三个锚点）。图层从下到上（命名沿用 Anime2.5DRig / See-through，便于两条产线互通）：

| 序 | 槽位 | 变体（首批目标） | 换色 | 活化 |
|---|---|---|---|---|
| 1 | `back_hair` 后发 | 女 8 / 男 4（长直、披散、半束、马尾、侧束…） | 发色渐变映射 | 弹簧 + 摆动着色器 |
| 2 | `body` 身体与袍 | 女/男各 3 种袍型（交领、对襟、披帛） | 袍色乘色（灰度底 + 调色板） | 呼吸（胸骨缩放 1.5%） |
| 3 | `robe_trim` 领缘/腰带 | 6 | 点缀色 | — |
| 4 | `neck` / `face` 脸型 | 女 4（鹅蛋、圆、瓜子、方圆）/ 男 3 | 肤色 3 档 | 点头（头骨 ±2°） |
| 5 | `eyes`（含 `eye_close`） | 杏眼、凤眼、垂眼、狐眼 × 开/闭 | 瞳色 4 | 眨眼交叉淡入 |
| 6 | `brows` | 柳叶、远山、平眉、剑眉 | 跟发色 | 表情时上下 2px |
| 7 | `nose` / `mouth` | 嘴 4（抿、浅笑、启唇、下撇=表情） | 唇色 3 | 说话时启唇层闪切 |
| 8 | `blush` / `mark` 花钿、泪痣 | 6 | — | — |
| 9 | `front_hair` 刘海 | 女 8（中分、斜刘海、齐刘海、空气刘海、高髻碎发…）/ 男 4 | 发色 | 发缕弹簧（根硬梢软） |
| 10 | `acc` 饰品 | 簪、步摇、发带、花、发冠、面纱、耳坠 | 金/玉/银/朱 | 步摇流苏弹簧 |

组合数：仅女修“脸×眼×眉×嘴×前发×后发×袍”≈ 4×4×4×4×8×8×3 ≈ 24.5 万，再乘调色板。**存档只存 `portrait.seed` 与玩家改过的槽位**（DiceBear 思路）。

### 5.2 换色
- 部件以“**接近白/灰的明暗图**”出产（袍、发），运行时着色器：袍=乘色（保留水墨明暗）；发=亮度→双色渐变映射（暗部色、亮部色），饰品等饱和像素不改。
- 调色板刻意**低饱和**（色值向白混 45%），保持“淡彩水墨”。正道偏青白、魔道偏黛紫/暗朱、散修偏茶褐——阵营一眼可读。

### 5.3 部件怎么产出
**主线（有 GPU 时）**：生图出统一画风的原画（每张都用同一模板构图）→ **See-through** 拆层（自动补画被遮住部分）→ 按 5.1 命名整理 → 灰度化需要换色的层 → 打包 webp。需 12–16 GB 显存（NF4 约 8 GB）；HF 免费 Space 每天只能 1–2 张，**box 上没有 GPU**。

**替代（现在就能跑，本次原型用的就是它）**：
1. 生图出一张**模板底图**（紧发髻、素白交领袍、白底，正面）；
2. 以底图为参考，做“**只加一件东西**”的编辑图（某发型 / 面纱 / 闭眼）；
3. `cut_parts.py`：多尺度模板匹配求初值 → ECC 仿射精修，把编辑图对齐回底图 → 与底图逐像素做 Lab 差 → 去掉皮肤/唇色、只留大块连通区域、脸与袍区域只认“更暗的发丝” → 得到透明部件 PNG；
4. 底图上用**手画一次的模板遮罩**（袍区多边形、发髻区）做运行时换色。

局限（原型里看得到）：①目前每个性别只有**一张脸**，脸型/五官变体需要再出若干张底图或单独的五官编辑图；②编辑图偶尔整体位移/缩放 5–8%，对齐能救回来，但发丝边缘仍有少量残影，需要人工过一遍；③面纱这种半透明件按“差分”抠不干净，宜单独在纯色底上出图。**正式版建议：底图 4 女 3 男，每张出 8 个发型编辑图 + 闭眼 + 3 个嘴型**，约 100 张生图，可一天内完成。

### 5.4 活化（Live2D-lite，全部 Godot 内置）
- **眨眼**：`eye_close` 层透明度 0→1→0（80 ms），间隔 2–6 s 随机，15% 连眨两次（Anime2.5DRig 做法）。原型图：`portrait/blink_crossfade.png`。
- **呼吸**：身体层以锁骨为轴竖向缩放 1.0↔1.012，周期 3.6 s，相位按种子。
- **发丝/步摇**：前发、后发切成 3–5 缕 Polygon2D（内部顶点），各绑 2–3 节 Bone2D，挂 SkeletonModification2DJiggle（根部刚度高、梢部低）；或回退到移植自 Anime2.5DRig 的双弹簧 GDScript。
- **风**：发梢与袖口加 canvas_item 摆动着色器（按 UV.y 增幅），与骨骼摆动叠加。
- **表情**：嘴/眉层闪切 + 0.1 s 交叉淡入；事件对白里由 DM4 的 `[#mood=笑]` 标签驱动。

### 5.5 玩家捏脸
创建页：大立绘占上 60%；下面一排**大图标槽位**（脸、眼、眉、嘴、前发、后发、袍、饰品、发色、袍色），点一下=该槽位换下一个，长按=列出缩略图；右上角“骰子”整体重随机、“锁”图标锁住喜欢的槽位后再随机。名字一键随机（起名库），可改。

## 8. 风险与待评审

1. **一致性 vs 随机**：NPC 行为太随机会像掷骰；需要“性格一致性”权重与“记忆驱动的选择”。请评审给出具体权重方案。
2. **文本量**：一年期骨架去重 43%。每模板 ≥4 变体、按关系阶段换说法，文字工作量约 300–400 句。
3. **立绘一致性**：替代产线每张底图一张脸，脸型多样性依赖底图数量；See-through 主线需 GPU（box 无 GPU，未测）。
4. **Jiggle 是实验 API**，未在手机 Web 上测过；已留回退。
5. **DM4 体积与 Web**：DM4 为纯 GDScript，需实测导出体积与首包时间（当前首包 gz 7.0 MB）。
6. **伦理与基调**：魔修致死、背叛等需保持“女修小说”的克制，不写血腥细节。
7. **存档迁移**：v0.5 存档与 v4 结构不兼容；按约定“不清档”，旧档另存为 `legacy`，新开一局。
